Duas Telas

Um app de verdade respeita o formato do aparelho e tem mais de uma tela. Uma biblioteca resolve cada uma das duas.

projeto da aula: 7-aula1109 · npm install && npm start
Parte 1 · Área segura
1

O aparelho come um pedaço da tela

Até agora a gente acertava o topo no olho:

paddingTop: 60,

Funciona no seu aparelho. Em cada outro o número certo é diferente: 24 num Android antigo, 54 no Pixel 9 do emulador. E embaixo ninguém descontou a barra de gestos.

Área segura é o pedaço da tela onde dá para desenhar sem nada do sistema em cima. O que sobra é do aparelho: relógio, bateria, notch, barra de gestos.

2

As duas peças

npx expo install react-native-safe-area-context

Sempre npx expo install, nunca npm install: ele escolhe a versão que combina com o SDK do projeto. A SafeAreaView que vem dentro do react-native está depreciada e só funciona no iOS.

SafeAreaProvider, uma vez, na raiz

// src/app/_layout.js
<SafeAreaProvider>
  <Stack />
</SafeAreaProvider>

SafeAreaView, em cada tela

Lê quanto o sistema ocupa em cada borda e aplica como padding. Troca a View raiz da tela: 

<SafeAreaView style={styles.tela}>
3

edges

Por padrão a SafeAreaView afasta das quatro bordas. Numa tela com cabeçalho o topo sobra: o cabeçalho já cuidou dele, e a SafeAreaView põe o mesmo espaço de novo, logo abaixo.

Com cabeçalho, edges={["bottom"]}. Sem cabeçalho, sem edges.

O paddingTop do seu estilo é outra coisa: é o respiro que você escolhe entre o cabeçalho e o primeiro elemento. Com ["bottom"] a SafeAreaView não põe nada no topo, então tirar esse paddingTop cola o conteúdo no cabeçalho.

E por que não uma SafeAreaView só, no _layout.js? Porque perfil.js não tem cabeçalho e quer o topo, e notas.js tem e não quer. Um valor só não serve para as duas.

Parte 2 · Navegação
4

Preparar o projeto

npx expo install expo-router react-native-screens expo-linking expo-constants expo-status-bar

Duas linhas de configuração:

// package.json
"main": "expo-router/entry",

// app.json
{ "expo": { "name": "aula1109", "slug": "aula1109", "scheme": "aula1109" } }

Apague o App.js. Quem manda agora é a pasta src/app/.

5

O arquivo é o endereço

Não existe lista de rotas. O caminho do arquivo dentro de src/app/ é a URL, letra por letra.

Arquivo Endereço
src/app/index.js /
src/app/notas.js /notas
src/app/perfil.js /perfil
src/app/_layout.js não é tela: envolve as outras
src/components/ fora de app/, não vira rota

index é a tela da pasta. Criar tela é criar arquivo. Um arquivo no lugar errado vira uma página que você não queria.

6

O Stack e o cabeçalho

O Stack do _layout.js empilha: abrir uma tela põe em cima, voltar tira do topo. Botão de voltar, gesto de arrastar e cabeçalho vêm junto.

O título do cabeçalho é o nome do arquivo. Para mudar, cada tela põe um Stack.Screen: 

<Stack.Screen options={{ title: "Minhas notas" }} />

// ou some com ele, só nesta tela:
<Stack.Screen options={{ headerShown: false }} />

Sem cabeçalho, nada segura o topo: a tela volta a precisar das quatro edges. É o caso do perfil.js.

7

Link e router

// toque do usuário
<Link href="/notas">Ver minhas notas</Link>

// navegação por código
router.push("/perfil");
router.back();

router é para quando a navegação acontece depois de algo: salvou e vai para a lista, fez login e vai para o painel.

Parte 3 · Consulta
8

Quando der errado

Faixa branca embaixo do cabeçalho.
Área segura duplicada. Use edges={["bottom"]}.
Tirei o paddingTop e o conteúdo colou no cabeçalho.
Esse paddingTop é espaçamento seu. Com ["bottom"] a SafeAreaView não mexe no topo.
Aviso: missing the required default export.
Falta export default na função da tela.
Tela preta: Unmatched Route.
O endereço não bate com nenhum arquivo. /Notas não é /notas. O link Sitemap nessa tela lista as rotas que existem.
